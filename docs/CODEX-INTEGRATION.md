# 在 Codex 中打开与随插件启动

版本仍为 0.1.11。控制页采用深灰背景、灰蓝控件和原生勾选框。

## 不发送聊天消息，直接打开

在 Codex 插件列表进入 Codex Pet 详情，点击“打开宠物”显示公仔；点击“打开桌宠设置”进入完整设置窗口。支持应用扩展的宿主还会提供“楪祈桌宠”侧栏或聊天面板控制页，其按钮为“打开宠物”“打开设置”。

本地市场安装的控制页链接：`codex://plugins/codex-pet@inori-pet-local/app/pet_control_panel`。根目录也提供“在Codex中打开桌宠.url”。此入口不发送聊天消息。更新后需要重启 Codex 重新加载插件；旧宿主未显示入口时仍可使用公仔右键设置。

## 随 Codex 启动

默认关闭。开启后只保存本机偏好；当 Codex 加载此插件并完成连接时，启动公仔，不打开设置窗口。不创建 Windows 开机登录项，不启动常驻监听小助手。

插件连接时机由 Codex 决定。如果宿主延后加载插件，公仔启动也会延后，不能保证刚打开 Codex 窗口就立即出现。每个插件服务进程只自动发起一次启动；重载插件或重启 Codex 可能再次发起启动。桌宠已有单实例保护。

关闭随启动开关不会立即退出当前公仔。公仔运行期间会通过已有本地桥接进程检查 Codex 桌面进程；先检测到 Codex，再连续两次确认它完全退出后，公仔正常保存并在数秒内退出。仅关闭窗口但 Codex 仍在后台运行时保留公仔。检查失败视为未知，不因状态不明而退出；首次未检测到 Codex 的独立手动启动也保持可用。此行为独立于随启动开关。

检查只在公仔运行期间进行，没有新增开机项或脱离公仔运行的常驻助手。命令行和额度查询使用的 codex.exe 不会被当成桌面 Codex。卸载先退出桌宠，再卸载插件。不要从历史备份运行旧的监听助手。

## 验证边界

自动检查覆盖插件连接启动的启用/停用与去重、两个按钮的不同启动参数、原生设置和真实控制页的勾选框与配色。控制页检查使用明确的模拟宿主，不能代替实际 Codex 页面显示验收。未为了测试关闭用户正在使用的 Codex；重启后的实际加载时机仍待观察。
